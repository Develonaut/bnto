# shell-run Security Findings

**Created:** October 20, 2026
**Evidence:** [Shell script injection safety report](../../research/reports/Shell%20script%20injection%20safety.md) (research notes alongside it)
**Tests:** `engine/crates/bnto/tests/shell_security/` — run `cargo test -p bnto --test shell_security`; list open findings with `-- --ignored`.

Every finding below is a test that attacks the real `bnto` binary. **Guards** hold today and run in CI, so a regression fails the build. **Open** findings are written as the behaviour we want and `#[ignore]`d with `OPEN SEC-xx`. Each one fails today (verified). A hardening PR un-ignores the tests it makes pass and flips the row to Guard.

Most payloads try to create a canary file. A test passes only if the canary never appears and the legitimate path still works. That check comes from a positive control in the same test, so a test can't pass just because a feature is missing.

## The model

- **Author vs data.** Whoever wrote the recipe is trusted only through consent: bundled recipes are reviewed, and other recipes are approved per SHA-256 of the definition. Template values (`{{fields}}`, `{{item}}`, `{{node}}`, `{{env}}`, URL input) are **data** and may be hostile, because file names, CSV cells and downloaded content all flow in. Data must never become code.
- **The rule every credible source converges on:** keep the code literal, and pass values out of band (argv, env or stdin), never spliced into script text. Peers use the same pattern: GitHub Actions env vars, Jenkins `withEnv`, Airflow `env=`, Alfred argv, Windmill `$1`.

## Script mode: the safe-script contract

`shell-run` runs a literal script with `{ "shell": "sh", "script": "...", "args": [...] }` as `<fixed shell path> [-p|-f] -c <script> bnto <args…>`. The engine guarantees the script text is exactly what consent showed, the shell is the real one, and the environment is cleared. What it can't see is how the script uses its values, so bundled and user scripts follow these rules:

- Read values only as `"$1"`, `"$2"`… or `"$@"`, always quoted. An unquoted `$1` word-splits and globs.
- No `eval`, and never splice a value into nested code: `sh -c "…$1…"`, `osascript -e "…$1…"`, `python3 -c "…$1…"`, `xargs sh -c`, `find -exec sh -c`.
- Put `--` before values a getopt-style tool could read as options. `--` only helps tools that honor it.
- Validate enum-like values with a `case` guard before using them.
- Values are always strings; `$0` is `bnto`.

PowerShell scripts (`"shell": "powershell"` on Windows, `"pwsh"` anywhere) run as `<fixed path> -NoLogo -NoProfile -NonInteractive -OutputFormat Text -EncodedCommand <script>` with nothing after it, because `-Command <script> <args>` appends the args to the code. Values arrive only as `$env:BNTO_ARG_1`…`N` and `$env:BNTO_ARG_COUNT`. The same engine guarantees hold; a PowerShell script follows these rules ([powershell-script-mode.md](../../decisions/powershell-script-mode.md)):

- Read values only as `$env:BNTO_ARG_n`. Interpolating one into a string (`"…$env:BNTO_ARG_1…"`) is text, not code.
- Never turn a value into code: no `Invoke-Expression`/`iex`, `[scriptblock]::Create(…)`, `Add-Type` with a value in its source, or `powershell -Command`/`cmd /c`/`Start-Process -ArgumentList` strings built from a value.
- Pass values to native programs as separate arguments (`& tool -- $env:BNTO_ARG_1`), and validate them first on Windows PowerShell 5.1: it doesn't escape embedded `"` for native programs, so a quote can split one value into several arguments. Prefer cmdlets and .NET calls.
- Validate enum-like values with `switch` or `-in` before use.
- A background process (keep-awake's Windows session) gets its values through environment variables too: set `$env:NAME` before `Start-Process`, and keep its code a literal `{ … }` scriptblock (encoded with `.ToString()`), so PSScriptAnalyzer lints it as code.

## Not yet covered by tests

- **Argument injection** (values starting with `-`) through fields. The fix (a per-field `noLeadingDash` validator or `--` insertion) isn't designed yet. A blanket ban would break `download-video`'s option-shaped enum values. Report recommendation 11.
- **Templated `searchPath`** lets a value choose the folder a command runs from. The shipped fixture uses `{{vars.Tools}}` (run config, not data). Whether `{{fields}}`/`{{item}}` should be allowed there is undecided. It's the same class as SEC-07.
